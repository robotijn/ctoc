# Dependency-analyzer agent, round 2: standards, agencies and peer-reviewed work

I read the agent in full: 1,132 lines, all dates 2026-10-01. I could not recompute the fingerprint because I have no shell. I edited nothing.

I used 25 of the 30 allowed fetches; 6 of them failed. I also ran 13 web searches. The two PDFs were saved by the fetch tool, and I read their pages as images; that cost no extra fetch.

**Bottom line**
- **Cycle severity.** The literature supports the round-1 rule that cycle severity follows the kind of cycle, not its length. Nothing I read grades harm by cycle length.
  - The rule is qualified, and the two qualifications disagree with each other:
    - Falleri and others (2011) rank cycles by how far apart the packages sit in the package tree.
    - Oyetoyan and others (2015) found that a cycle's place in that tree does not separate harmful cycles from harmless ones.
  - That disagreement belongs in the agent, stated, rather than settled quietly.
- **Strongly connected components as the unit.** This is supported for counting and refuted as sufficient evidence for a fix. In large components, one path per component leaves most edges unexplained.
- **The `skipTypeImports` sentence is now partly refuted by madge's parser source.** With that setting, madge also drops an import whose every name carries an inline `type` modifier. This agent counts that import as runtime. So the advice that the setting makes madge "skip such edges as this agent does" over-claims.

## 4. Gaps: facts the agent lacks that these sources make load-bearing

1. **Evidence for large components** (Step 4, lines 128–131). Real systems carry components of 18–61 packages (Falleri, Table 1 and section 4.1). One path per component leaves the fixer blind. The script should list every import edge inside the component with file and line, or one shortest cycle through each edge (polynomial, as in the cited paper). Both are within what Bash can run.
2. **State the locality choice and its basis** (line 194). Add the 2015 change-proneness sentence as the empirical reason the agent does not grade by package-tree location. Name Falleri's ranking by tree distance as the published counter-position. The two sources disagree; the file should show that rather than settle it silently.
3. **Priority tie-break** (line 1003). "Most files first" is the opposite of the published tie-break: fewer packages first, because short cycles are easier to understand. Either keep it, say it is a deliberate departure, and give the reason (a larger tangle ties more files together), or switch to fewest files first.
4. **madge's `skipTypeImports` drops all-inline-type imports** (line 1053). The recipes and the agent would then disagree in the dangerous direction: the recipe passes, the agent reports high. Exact correction is in section 1.
5. **Count units differ across tools** (lines 138, 1085, 1095). This agent counts components; madge, ArchUnit (capped at 100) and Sonar count cycles. The hook's "N circular dependencies" needs labelling as madge's count, or a reader will compare unlike numbers.
6. **Layer skips under ISO/IEC 5055** (Step 5, line 169). The defaults let every upper layer import domain and models directly. Under CWE-1054 that is a "Layer-skipping Call" unless those layers are declared vertical. The agent should either say "the defaults treat domain, models and utils as layers any higher layer may import" or align with the standard. It could also give the standard's name, CWE-1054 in ISO/IEC 5055 clause 7.1.11, for its controller-to-repository finding, and CWE-1047, clause 7.1.25, for cycles.
7. **Harm reaches the importers of a cycle.** "Either directly or indirectly" (2013) and "classes near these cycles" (2015) back the agent's use of afferent counts in priority and impact. That use is currently uncited.
8. **Test-file recognition, reasoned and not sourced.** The patterns at lines 492–493 do not match Python's `conftest.py` or a .NET test project directory such as `MyApp.Tests/`, so those test-only cycles would be graded high. pytest and .NET conventions were not fetched.
9. **Files that fail to parse, reasoned.** Nothing says what happens when a Python file raises a syntax error in `ast`, or a TypeScript file does not parse. A per-file failure is not the whole-run stop that line 47 covers. It should go under "Limits of this run" and never be dropped silently.
10. **Other findings checked:**
    - **Orders the tools cannot carry out:** none new. Every new suggestion above is script work under Bash.
    - **Claims that a mechanism runs:** none. The GitHub Actions job is still not run (round-1 note).
    - **Untrusted content:** the rule is present at line 28. No fetched page addressed a reviewer; the HAL failure was a plain access-denied page.
    - **Invented abbreviations:** none. The capitalised forms are real names (PHP, JSON, PNG, SVG, DOT, README), words inside verbatim titles (OO in Martin's title, FAQ, SE), or the defined symbols Ca, Ce and I. A strict reading of house rule 13 could still ask for JSON, PNG and SVG to be spelled out; that is low priority.
    - **Gate numbers in prose:** none (checked by an exact search; the frontmatter `tier: 2` is a machine key).
