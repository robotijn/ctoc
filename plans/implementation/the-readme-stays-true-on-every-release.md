## Original functional plan

### 1. ASSESS — Problem Understanding

A full read of the shipped `README.md` (1,177 lines, 2026-09-03) against disk found
four defects:

1. **The Lesson 2 dashboard capture opens `CTOC v6.14.36`** while the badge says
   6.14.63. `release.js` `VERSION_UPDATES` rewrites only the badge, the line-start
   `**X.Y.Z**` token and the `getVersion()` example — a version inside a fenced
   capture is invisible to it, so the capture re-rots on every release forever.
2. **The promise "Every screen you see below is a real capture from the current
   version"** is broken by 1 the moment any release lands: the machinery cannot
   keep a promise about "the current version" for text it does not sync.
3. **The structure block says `tests/ 524 test files`; disk holds 543.**
   `release.js` `COUNT_UPDATES` keeps CLAUDE.md's growing counts true but does not
   target README.md, so README counts drift with every added test file.
4. **The Environments table's staging row claims "auto-move to review" — false.**
   `src/lib/settings.js` deleted `autoMoveToReview` (R4-B: it drove an
   evidence-less rename into review; a plan reaches review only through the
   evidence-minting completion). The cell was carried from the old README
   unverified.

Verified true and NOT in scope: every other number and claim — badge and lead
counts, the agent table (sums to 124), the skills taxonomy (101 + 328), lib-module
/ hook / script / area / tab / doc counts, the tier table (per
`docs/AGENT_ARCHITECTURE.md`), the escape-phrase list (matches
`escape-phrases.js`), the settings-file split (matches `CONFIG_SOURCES.md`),
"14 languages" (matches `LANGUAGE_PATTERNS`), the dev and prod environment cells
(match `ENVIRONMENT_PROFILES`).

### 2. ALIGN — Approach

Fix the content once, then make the drift impossible — the same discipline the
repository already applies to CLAUDE.md's counts:

1. **Refresh the Lesson 2 capture** with today's real dashboard output (taken this
   session from `node src/commands/start.js dashboard`: `CTOC v6.14.63`, Business
   2, Implementation 4, Execution 396 with Review 134 / Done 262, the real TASKS
   and INBOX lines). Adjust the two prose sentences that read the capture's
   numbers if they name any (the lesson's prose is structural, not numeric — verify).
2. **Correct the promise**: "Every screen you see below is a **real capture** —
   nothing is mocked up. A capture is a snapshot of a live repository, so its
   plan counts show that moment; the version line always shows the current
   version (the release sync keeps it true)." — accurate about both halves.
3. **Delete the false staging cell text**, replacing "auto-move to review" with
   what the profile actually does ("strict enforcement; nothing else changes").
4. **Sync machinery**:
   - `src/scripts/release.js` `VERSION_UPDATES` gains one README pattern:
     `/^CTOC v\d+\.\d+\.\d+$/m` → `CTOC v<version>` (the capture's first line).
   - `release.js` `COUNT_UPDATES` currently targets only CLAUDE.md; extend the
     mechanism so README.md's `tests/           <N> test files` and
     `lib/         <N> JS modules` structure-block lines are rewritten from
     `computeDocCounts`, exactly as CLAUDE.md's are (line-targeted patterns,
     number-only rewrites; fail loudly when a pattern stops matching, per the
     existing `syncToReadme` FAIL LOUD contract).
   - `src/lib/version.js` `syncToReadme` mirrors the new capture-version pattern
     (it documents itself as rewriting "the same targets the release script
     rewrites" — keep that sentence true).
5. **Tests, red first**: `tests/release-script-coverage.test.js` gains cases
   driving a fixture README carrying a capture line + structure counts through the
   sync and asserting the rewrites (and the loud failure when the token is
   absent); `tests/version.test.js` keeps its tracked-README drift case green;
   `tests/readme-numbers.test.js` gains a derived pin: the structure block's
   test-file count equals `computeDocCounts(ROOT).testFiles` (so a future drift
   is red, not silent).

#### Scope

**In scope:** the four defects, the sync machinery, the tests above.
**Out of scope:** refreshing the Lesson 4/5 captures (internally consistent
snapshots, no version string inside them); the tier-count source-of-truth
disagreement (recorded previously; the README follows the architecture document).

### Decisions Taken Under Ambiguity

1. **Sync the capture's version, snapshot its counts.** A README cannot track live
   plan counts and should not pretend to; the version is special because the badge
   beside it always shows the current one, so a mismatch reads as rot. The
   reworded promise states exactly that split.
2. **Lesson 4/5 captures stay as snapshots** — they contain no version string and
   are internally consistent; refreshing them on every release would churn the
   file for no reader benefit.
